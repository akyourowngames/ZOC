# Deep Notes

## Core logic

The even numbers below `N` are generated by a counter that starts at `2` and
advances by `2`. Because the counter is always even, no parity test is needed:

```cpp
sum = 0;
i = 2;
while (i <= N) {
    sum += i;
    i += 2;
}
```

The number of iterations is the number of terms, `m = N / 2` with integer
division, and the total is the arithmetic series

```text
2 + 4 + ... + 2m = 2 * (1 + 2 + ... + m) = m * (m + 1)
```

## Code walkthrough

```cpp
int N,i,sum;
cin >> N;
sum = 0;
i = 2;
```

`sum = 0` is required; `i = 2` encodes both the starting value and the parity of
the series. The declaration `int N,i,sum;` mixes input, counter, and accumulator,
which is compact but makes the roles less obvious than three separate lines.

```cpp
while (i <= N) {
    sum += i;
    i += 2;
}
cout << sum;
```

`i += 2` is the entire "skip odd numbers" logic. Omitting `i += 2` would loop
forever; changing it to `i++` would include odd numbers. `<=` keeps the term
equal to `N` when `N` is even. No newline is printed.

## Why it works

After `k` iterations the loop has added `2, 4, ..., 2k` exactly once, so the
running total is the first `k` even numbers. The loop stops at the first `k` with
`2k > N`, which is `k = floor(N / 2) = N / 2` in integer arithmetic. That single
fact explains both the term count and why an odd `N` behaves like `N - 1`.

The closed form is worth deriving once, because it is the tool for large `N`:

- `m = N / 2` is the count of even values in `[1, N]` (integer division drops the
  leftover odd number).
- Factoring out `2` leaves `1 + 2 + ... + m = m(m+1)/2`.
- Multiplying back by `2` gives `m(m+1)`.

For `N = 8`: `m = 4`, total `20`. For `N = 9`: `m = 4`, total `20`. The formula
and the loop agree on both parities, which is a good cross-check.

## Complexity

- Loop: `N / 2` iterations → `O(N)` time, `O(1)` space.
- Formula: `O(1)` time, `O(1)` space.
- Iteration count for `N = 100` is `50`; for `N = 92681` it is `46340`.

## Edge cases and tests

| Input | Expected | Reason |
| --- | --- | --- |
| `0` | `0` | no even positive integer `<= 0` |
| `1` | `0` | same |
| `2` | `2` | single term |
| `3` | `2` | `3` is odd, ignored |
| `4` | `6` | `2 + 4` |
| `8` | `20` | README example |
| `9` | `20` | odd endpoint rounds down |
| `10` | `30` | adds `10` |
| `100` | `2550` | `50 * 51` |
| `92680` | `2147441940` | `m = 46340`, last safe `int` pair |
| `92682` | `2147534622` | code prints `-2147432674` — overflow |
| `-5` | `0` (undefined case) | condition false immediately |

## Common mistakes

- `i++` instead of `i += 2`, then summing odd values too.
- `i < N` instead of `i <= N`; `N = 8` then returns `12`.
- Starting at `0`: numerically harmless, but it misstates the series and breaks
  if the problem later asks for the term count.
- Using `N * (N + 1) / 2` instead of the even-series formula; that sums all
  integers, so `N = 8` returns `36` rather than `20` (roughly double for large
  even `N`).
- `int` accumulator with a large `N`; the total grows as `N^2 / 4`.
- Forgetting `sum = 0` so the first addition uses stack garbage.

## Variants and follow-ups

1. **Closed form:** `long long m = N / 2; cout << m * (m + 1);` — `O(1)`.
2. **Multiples of `k`:** `k * m * (m + 1) / 2` with `m = N / k`, or a loop with
   `i += k` starting at `k`.
3. **Count instead of sum:** the answer is simply `N / 2` (see
   `14-number-of-even-numbers`).
4. **Range `[a, b]`:** compute `prefix(b) - prefix(a - 1)` with the closed form
   to keep it `O(1)`.
5. **Sum of odd numbers:** start at `1` and step by `2`; the total is `k^2` where
   `k` is the count, a classic identity worth verifying on `N = 9` (`1+3+5+7+9 = 25 = 5^2`).

## Key takeaways

- A stride can encode a filter; `i += 2` is cheaper and clearer than
  `if (i % 2 == 0)`.
- Integer division quietly implements "largest even `<= N`".
- Any `O(N)` series with a fixed step has an `O(1)` formula; know both forms.
- Sum-shaped answers grow quadratically, so the accumulator type must be chosen
  from the answer's magnitude, not the input's.

## Current-code review

The loop computes exactly `2 + 4 + ... + (largest even <= N)` for all
`0 <= N <= 92681`, so it matches the README. Remaining issues:

1. **`int` overflow at `N = 92682`.** Verified: prints `-2147432674` instead of
   `2147534622`. Signed overflow is undefined behaviour in C++, though GCC and
   Clang wrap in practice. Fix with `long long sum = 0;` (the loop body and
   bound are unchanged).
2. **Counter overflow risk near `INT_MAX`.** If `N` were `2147483647`, `i += 2`
   eventually steps from `2147483646` to `-2147483648`, which satisfies
   `i <= N` and restarts the loop with negative values — an infinite loop. The
   sum overflows far earlier, so widening only `sum` is not sufficient for such
   inputs; widening `i` as well is required.
3. **Negative input** prints `0` silently rather than rejecting an out-of-domain
   value.
4. **No trailing newline** after `cout << sum;`.

The arithmetic itself is correct, including the odd-`N` rounding; there is no
off-by-one in the bound.
